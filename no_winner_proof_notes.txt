If +n has strategy [0,0,0] then +(n+1) must be [x,0,x] since player 2 cannot prevent player 1 from going to the +n configuration. In fact, +(n+1) must actually be [x,0,0] because player 3 can't stop player 1 from going to +n. 

So only need to consider if (first to play on gap game) = (player 2) has a winning strategy.

From game tree at n = N+1 there are ways to stay out of positions generated in game tree for n = N (as long as player doesn't meld), but we can't *stop* a player from forcing back into one via melding. In fact, we can have 2 players collude to show there is no winning strategy for the other. Can look 2 ahead for no winner node.

Define property *
	- A layer has property * if for all nodes in the layer, there exists a child node with winning strategy [0,0,0]. That is, nobody can win from this position.

Suppose at k=K we have our * property. Then at +(K+2) any P1-move to layer k = K+1 can be melded into the previous +(K+1) game tree by P2-move. This in in time have P3-move to a node with no winning strategy.

Therefore if we find at k = K the * property via searching from game K+1, then player 1 at +(K+2) has no winning strategy.

Hold on, we need it to be for every possible partition at a layer k. The reason is as follows:

for very large games, we can't conclude that it will get all the way into one of the nodes we calculated unless we have confirmed that we have every possible position at layer k=K. This means every signed partition of K with even parity.

If we have that, then we can be sure that there is no winning strategy.

Moreover, we can actually relax the condition that the terminal node is [0,0,0]. As long as the node is [0,x,x] we know that the player whose turn it is at the terminal node doesn't have a winning strategy.
